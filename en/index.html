The programs

All of them run on Windows, Linux and macOS, with nothing else to install. They are support tools: responsibility for the design lies with the engineer who signs it.

How to download, install and report

You don't need to know how to program or how GitHub works. GitHub is the site that holds the programs' code, their downloadable releases and the list of reports.

  1. Download the latest release

    On the program's page, open Releases (or use the Download button on each card, which goes straight to the latest release). Scroll down to Assets and pick the file for your system:

    ProgramWindowsLinuxmacOS

    Skip the Source code files: they hold the source, not the program.

  2. Open it the first time

    The programs are not code-signed yet, so your system asks for confirmation once:

    • Windows: if "Windows protected your PC" appears, click More info and then Run anyway. If you downloaded a .zip, unzip the whole folder before opening the .exe.
    • macOS: right-click the app and choose Open. On macOS 15 or later: try to open it once, then go to System Settings › Privacy & Security › Open Anyway.
    • Linux: make the .AppImage executable (chmod +x) and run it.

    OpenSees Studio also asks you to install the OpenSees solver the first time, from Options › Solver; the program downloads it after you accept its license.

  3. Create a free GitHub account

    You only need it to report or comment, not to download. Sign up at github.com/signup with your email. Once you have an account, click Star on the programs you use (it helps others find them) and, under Watch › Custom › Releases, turn on notifications for new releases.

  4. Report a problem or propose an improvement

    Open the program's Issues tab and click New issue (or use the Report or propose button on each card). Pick the template that fits and fill in the form; each field says what to write.

    • Give the version (it is in the name of the file you downloaded, or in Help › About).
    • Drag screenshots and the model file into the form. If GitHub refuses the extension (.ocnx, .osmodel, .smj), zip it first.
    • Before sending, check whether someone already reported the same thing; if so, comment there.

    You can write in English or Spanish.

  5. Ask in Discussions

    How-to questions ("how do I model…?", "which code applies…?") and ideas that are not yet shaped go to each program's Discussions tab, not to Issues. News and new releases are announced there too.

  6. If you program: contribute code

    Fork the repository, create a branch, make your change with its tests and open a pull request against main. Each project's CONTRIBUTING.md explains how to set up the environment and what to check before sending. Issues labelled good first issue are a good place to start.

How to get involved, by what you do best

What these programs need most is not code: it is engineers who use them on real work and tell us where they fail or what is missing.

Practising engineers

Contribute validation cases: an example from a design guide or a textbook, your hand calculation or another program. Each case becomes an automated test that runs on every change.

Teachers and students

Use the programs in class, write tutorials and examples, or take a new feature or a validation as a thesis topic. The bundled examples are written to read as study material.

Programmers

Python and Qt in OpenConex, OpenFEMConex and OpenSees Studio; Rust and TypeScript in IngeCalc. Start with a good first issue.

Translators and designers

Translate the interface and the manuals, improve icons and screens, or check that the help reads clearly.

When you contribute an example, cite the source and share only the numbers: do not copy text, tables or figures from copyrighted codes or books.
